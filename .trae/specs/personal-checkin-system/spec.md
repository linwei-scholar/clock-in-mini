# 个人打卡系统 - 产品需求规格说明书

## 一、项目概述

### 1.1 项目背景与目标

在现代快节奏的生活中，越来越多的人开始重视习惯养成和个人成长。一个高效、美观、易用的打卡系统能够帮助用户建立和坚持良好的生活习惯，如运动健身、合理膳食、阅读学习等。本项目旨在打造一款面向个人用户的轻量级打卡工具，通过直观的日历视图、丰富的统计报表和便捷的操作体验，帮助用户养成健康的生活方式。

### 1.2 核心价值主张

本系统以**简约而不简单**为设计理念，在保持界面简洁清爽的同时，提供强大的功能和优秀的使用体验。通过可视化的数据统计和灵活的打卡计划管理，让用户能够清晰地看到自己的成长轨迹，从而获得持续前进的动力。

### 1.3 目标用户画像

本系统主要面向有以下需求的用户群体：

- 希望养成早起、运动、阅读等良好习惯的职场人士
- 需要记录和追踪健身计划、饮食控制的健身爱好者
- 想要建立阅读习惯、培养学习能力的知识追求者
- 需要管理日常事务、提升生活效率的时间管理者
- 关注个人成长、追求自我提升的终身学习者

## 二、系统架构设计

### 2.1 技术选型

#### 2.1.1 前端技术栈

- **核心框架**：Vue 3（组合式API + Script Setup）
- **构建工具**：Vite
- **路由管理**：Vue Router 4
- **状态管理**：Pinia
- **UI组件库**：Element Plus
- **图表库**：ECharts
- **日历组件**：FullCalendar
- **样式方案**：SCSS + CSS变量
- **图标库**：Element Plus Icons

#### 2.1.2 数据存储方案

采用**纯前端本地存储**方案，所有用户数据均保存在浏览器本地存储中，包括：

- **localStorage**：存储用户基础配置和轻量级数据
- **IndexedDB**：存储大量打卡记录和统计数据
- **数据导出/导入**：支持JSON格式的完整数据备份和恢复

#### 2.1.3 用户认证机制

采用**用户名+密码**的本地认证方式：

- 用户注册时设置用户名和密码
- 密码经过SHA-256哈希加密后存储
- 登录时验证密码哈希值
- 用户数据通过用户名进行隔离

## 三、功能需求详述

### 3.1 用户认证模块

#### 3.1.1 用户注册

- **功能描述**：新用户通过设置用户名和密码创建账户
- **输入要求**：
  - 用户名：4-20个字符，支持字母、数字、下划线，不可重复
  - 密码：6-20个字符，至少包含字母和数字
- **验证规则**：
  - 用户名唯一性验证
  - 密码强度验证
  - 确认密码一致性验证
- **业务逻辑**：
  - 注册成功后自动登录
  - 创建用户专属的数据存储空间
  - 初始化默认类别标签

#### 3.1.2 用户登录

- **功能描述**：已注册用户通过用户名和密码登录系统
- **输入要求**：
  - 用户名：已注册的用户名
  - 密码：对应的密码
- **验证规则**：
  - 用户名存在性验证
  - 密码正确性验证（哈希比对）
- **业务逻辑**：
  - 登录成功后加载用户数据
  - 记录最后登录时间
  - 登录失败需等待30秒后重试（防暴力破解）

#### 3.1.3 密码重置（管理员功能）

- **功能描述**：通过管理员Token验证后重置用户密码
- **访问条件**：
  - 需要输入管理员固定Token
  - Token值记录在系统README文档中
- **操作流程**：
  1. 用户列表页面显示所有已注册用户
  2. 选择需要重置密码的用户
  3. 输入管理员Token验证身份
  4. 验证通过后将密码重置为默认密码：AaBb@123456
- **安全考虑**：
  - Token作为本地安全凭证，仅开发者知晓
  - 不提供原密码找回，仅能重置为默认值

#### 3.1.4 用户登出

- **功能描述**：用户退出当前登录状态
- **业务逻辑**：
  - 清除当前会话状态
  - 跳转到登录页面
  - 保留本地数据

### 3.2 类别标签管理模块

#### 3.2.1 类别标签概念

类别标签是用于组织和分类打卡计划的元数据，每个打卡计划可以关联一个或多个类别标签，便于用户从不同维度管理自己的习惯养成计划。

#### 3.2.2 系统默认标签

系统预设以下默认类别标签，用户可自行修改或删除：

| 标签名称 | 标签图标 | 标签颜色 | 适用场景 |
|---------|---------|---------|---------|
| 运动健身 | running | #409EFF（蓝色） | 跑步、健身、瑜伽等 |
| 合理膳食 | food | #67C23A（绿色） | 健康饮食、断食、饮水 |
| 阅读学习 | book | #E6A23C（橙色） | 读书、课程、学习 |
| 习惯养成 | star | #909399（灰色） | 早起、早睡、冥想 |
| 工作任务 | briefcase | #F56C6C（红色） | 工作计划、项目跟进 |
| 兴趣爱好 | heart | #9B59B6（紫色） | 绘画、音乐、摄影 |

#### 3.2.3 标签CRUD操作

- **创建标签**：
  - 输入标签名称（必填，2-10个字符）
  - 选择标签图标（从预设图标库选择）
  - 选择标签颜色（预设配色方案）
  - 标签名称不可重复

- **编辑标签**：
  - 可修改标签名称、图标、颜色
  - 编辑后自动同步到所有关联的打卡计划

- **删除标签**：
  - 删除前需确认是否保留关联的打卡计划
  - 可选择将关联打卡计划的标签设为"无"
  - 系统默认标签删除后不可恢复

### 3.3 打卡计划管理模块

#### 3.3.1 打卡计划概念

打卡计划是用户创建的用于追踪习惯养成的任务模板，定义了需要坚持的行为、目标、频率等属性。

#### 3.3.2 打卡计划属性

| 属性名称 | 属性类型 | 必填 | 说明 |
|---------|---------|-----|------|
| 计划名称 | 文本 | 是 | 4-30个字符，简明扼要 |
| 计划描述 | 文本 | 否 | 详细说明，0-200个字符 |
| 关联标签 | 多选标签 | 否 | 可关联0-3个标签 |
| 打卡频率 | 枚举 | 是 | 每日、每周、工作日、周末、自定义 |
| 循环规则 | JSON | 否 | 自定义循环规则配置 |
| 开始日期 | 日期 | 是 | 计划开始执行的时间 |
| 结束日期 | 日期 | 否 | 计划结束时间，空值表示永久有效 |
| 目标次数 | 数字 | 否 | 计划周期内的目标次数 |
| 提醒时间 | 时间 | 否 | 每日打卡提醒时间 |
| 提醒开关 | 布尔 | 否 | 是否启用提醒 |

#### 3.3.3 循环计划配置

**每日打卡**：每天都需要打卡

**每周打卡**：
- 可选择周几打卡（可多选）
- 示例：每周一、三、五打卡

**工作日打卡**：
- 仅工作日（周一至周五）打卡

**周末打卡**：
- 仅周末（周六、周日）打卡

**自定义循环**：
- 支持设置间隔天数
- 示例：每3天打卡一次
- 支持设置每月第几周周几
- 示例：每月第二周周五

#### 3.3.4 打卡计划CRUD操作

- **创建计划**：
  1. 填写计划基本信息
  2. 设置打卡频率和循环规则
  3. 关联类别标签（可选）
  4. 配置提醒设置（可选）
  5. 确认创建

- **编辑计划**：
  - 可修改所有属性
  - 修改循环规则不影响历史打卡记录
  - 删除计划需二次确认

- **暂停/恢复计划**：
  - 暂停后计划不生成打卡任务
  - 暂停期间不计入统计
  - 可随时恢复

- **归档计划**：
  - 已结束的计划可归档
  - 归档后不显示在主列表
  - 可在归档区查看和恢复

### 3.4 打卡日历模块

#### 3.4.1 日历视图类型

**周视图**：
- 显示当前周的7天
- 每列显示一天的打卡情况
- 可左右滑动切换周
- 适合短期习惯追踪

**月视图**：
- 显示当前月的完整日历
- 每天格子显示打卡完成状态
- 可点击日期查看当日打卡详情
- 适合中长期规划

**年视图**：
- 显示12个月的迷你日历
- 每月用颜色深浅表示完成度
- 可点击月份放大查看
- 适合年度目标追踪

#### 3.4.2 日历视图功能

- **打卡状态显示**：
  - 已完成：绿色勾选标记
  - 未完成：灰色圆圈标记
  - 无任务：空白
  - 逾期未打：红色叉号标记

- **多计划显示**：
  - 支持在同一日历上显示多个计划
  - 可筛选显示特定计划
  - 不同计划用不同颜色区分

- **视图切换**：
  - 提供视图切换标签栏
  - 记住用户偏好的视图类型
  - 支持键盘快捷键切换

#### 3.4.3 日期交互

- **点击日期**：
  - 查看当日所有打卡记录
  - 可补录历史打卡
  - 可查看打卡详情

- **拖拽操作**：
  - 周视图支持拖拽切换周
  - 月视图支持拖拽切换月

### 3.5 打卡执行模块

#### 3.5.1 快速打卡

- **入口**：
  - 首页快捷打卡按钮
  - 日历日期点击
  - 计划列表打卡操作

- **打卡内容**：
  - 文本记录：最多500个字符
  - 图片上传：最多9张，单张不超过5MB
  - 表情选择：预设常用表情符号
  - 内容可以不填，直接确认打卡

- **操作流程**：
  1. 选择要打卡的计划
  2. 填写打卡内容（可选）
  3. 添加图片或表情（可选）
  4. 点击确认打卡
  5. 显示打卡成功反馈

#### 3.5.2 打卡记录查看

- **记录详情**：
  - 显示打卡时间
  - 显示打卡内容
  - 显示关联的图片
  - 显示打卡状态

- **记录编辑**：
  - 允许修改打卡内容
  - 允许添加或删除图片
  - 记录修改时间

- **记录删除**：
  - 删除前需二次确认
  - 删除后不可恢复

#### 3.5.3 历史补卡

- **补卡规则**：
  - 最多补最近7天的打卡
  - 补卡需要填写打卡内容
  - 补卡计入当日统计

### 3.6 统计分析模块

#### 3.6.1 统计指标体系

**基础统计指标**：

| 指标名称 | 计算方式 | 说明 |
|---------|---------|------|
| 应打卡次数 | 计划周期 × 频率 | 理论上应完成的次数 |
| 实际打卡次数 | 实际打卡记录数 | 实际完成的次数 |
| 完成率 | 实际次数 / 应打卡次数 × 100% | 完成百分比 |
| 连续打卡天数 | 最长连续打卡记录 | 最长不间断天数 |
| 当前连续天数 | 截止今日连续天数 | 当前坚持天数 |
| 总打卡天数 | 所有打卡记录去重天数 | 累计打卡天数 |

**高级统计指标**：

| 指标名称 | 计算方式 | 说明 |
|---------|---------|------|
| 打卡趋势 | 环比增长率 | 与上一周期对比 |
| 最佳打卡时段 | 打卡时间分布 | 大多数打卡的时间 |
| 打卡间隔分析 | 平均间隔天数 | 两次打卡的平均间隔 |
| 完成率波动 | 标准差 | 完成率的稳定性 |
| 周末 vs 工作日 | 对比分析 | 不同时段的表现 |

#### 3.6.2 可视化图表

**圆饼图**：
- 用于展示完成率分布
- 示例：已完成vs未完成
- 支持交互：点击查看详情
- 配色清晰，易于理解

**柱状图**：
- 用于展示周期完成情况
- 示例：每周完成次数对比
- 支持时间范围选择
- 支持堆叠显示多计划

**折线图**：
- 用于展示打卡趋势变化
- 示例：30天完成率走势
- 支持平滑曲线
- 支持标记关键节点

**热力图**：
- 用于展示长期打卡情况
- 类似GitHub贡献图
- 颜色深浅表示强度
- 适合年度回顾

#### 3.6.3 统计报表功能

- **时间范围筛选**：
  - 今日/本周/本月/本年
  - 自定义日期范围
  - 支持快捷日期选择

- **计划筛选**：
  - 按标签筛选
  - 按单个计划筛选
  - 支持多选组合

- **数据导出**：
  - **JSON格式**：
    - 完整数据备份
    - 包含所有记录和配置
    - 支持完整数据恢复
  - **CSV格式**：
    - 适合Excel分析
    - 包含时间、计划、内容等字段
    - 支持按计划和时间范围导出
  - **Excel格式**：
    - 格式美化的报表
    - 包含汇总统计
    - 支持图表导出

### 3.7 打卡提醒模块

#### 3.7.1 提醒机制

采用**浏览器通知API**实现打卡提醒功能：

- **前提条件**：
  - 用户授权浏览器通知权限
  - 浏览器支持Notification API
  - 网站使用HTTPS或localhost访问

- **提醒触发**：
  - 到达设定时间自动触发
  - 仅在工作日/休息日规则下提醒
  - 浏览器需在后台运行

#### 3.7.2 提醒配置

- **单个计划提醒**：
  - 设置每日提醒时间
  - 开启/关闭提醒开关
  - 可设置提前提醒（5分钟/15分钟/30分钟）

- **全局提醒设置**：
  - 批量开启/关闭所有计划提醒
  - 设置勿扰时段（如22:00-08:00）
  - 提醒声音开关

#### 3.7.3 提醒内容

- **通知标题**：打卡提醒 - [计划名称]
- **通知内容**：今天是您计划打卡的日期，点击立即打卡！
- **点击行为**：打开系统并定位到对应计划

## 四、非功能性需求

### 4.1 性能需求

- **首屏加载时间**：不超过2秒
- **页面切换响应**：不超过200毫秒
- **数据查询响应**：不超过500毫秒
- **支持最大数据量**：
  - 用户数：不限（本地存储）
  - 打卡计划数：不限
  - 打卡记录数：支持至少10000条

### 4.2 兼容性需求

- **浏览器支持**：
  - Chrome 80+
  - Firefox 75+
  - Safari 13+
  - Edge 80+
- **响应式设计**：
  - 支持桌面端（1920px+）
  - 支持笔记本（1366px+）
  - 支持平板（768px+）
  - 支持手机（375px+）

### 4.3 安全需求

- **密码加密**：使用SHA-256哈希存储
- **数据隔离**：用户数据按用户名隔离
- **敏感操作**：需二次确认
- **数据备份**：支持手动导出备份

### 4.4 可用性需求

- **无网络依赖**：完全离线可用
- **数据持久化**：刷新页面数据不丢失
- **错误处理**：友好的错误提示
- **操作反馈**：及时的状态反馈

## 五、用户界面设计规范

### 5.1 视觉风格

采用**简约现代风格**，特点如下：

- **整体风格**：简洁清爽，大量留白
- **设计语言**：扁平化设计，轻量阴影
- **色彩体系**：主色蓝色，搭配中性色系
- **字体排版**：清晰易读，层次分明
- **交互动效**：流畅自然，轻盈灵动

### 5.3 字体规范

- **主字体**："PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif
- **标题字号**：
  - H1：28px，粗体
  - H2：24px，粗体
  - H3：20px，中等
  - H4：16px，中等

## 八、系统安全考虑

### 8.1 密码安全

- 密码使用SHA-256哈希存储，不可逆
- 不存储明文密码
- 不提供密码找回功能（本地系统限制）

### 8.2 管理员Token

- 固定Token存储在前端代码中
- Token仅用于本地密码重置
- 不传输敏感信息

### 8.3 数据安全

- 用户数据完全隔离
- 无网络传输，本地存储
- 定期建议用户导出备份

### 8.4 XSS防护

- 所有用户输入进行转义
- 图片使用Base64存储，不执行脚本
- 遵循Vue安全最佳实践

## 十、风险评估与应对

### 10.1 技术风险

| 风险项 | 风险等级 | 应对措施 |
|-------|---------|---------|
| 浏览器兼容性 | 中 | 使用兼容性检测，优雅降级 |
| 本地存储限制 | 低 | 使用IndexedDB替代localStorage |
| 通知权限拒绝 | 中 | 提供友好的提示引导用户开启 |

### 10.2 数据风险

| 风险项 | 风险等级 | 应对措施 |
|-------|---------|---------|
| 浏览器清除数据 | 高 | 提供数据导出备份功能 |
| 多浏览器数据不同步 | 低 | 明确告知用户数据隔离性 |
| 忘记密码无法找回 | 中 | 提供管理员Token重置方案 |

### 10.3 用户体验风险

| 风险项 | 风险等级 | 应对措施 |
|-------|---------|---------|
| 学习成本高 | 中 | 简化操作流程，提供引导 |
| 功能过于复杂 | 中 | 突出核心功能，隐藏高级选项 |
| 移动端体验差 | 低 | 响应式设计，重点优化移动端 |
