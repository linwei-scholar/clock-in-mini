# 个人打卡系统

## 项目介绍

### 项目简介

个人打卡系统是一款功能完善的习惯追踪与打卡管理应用，旨在帮助用户养成良好的生活习惯和坚持完成各项计划。通过可视化的日历视图、丰富的统计图表和灵活的提醒功能，用户可以轻松记录每日的打卡情况，并对自己的坚持成果有清晰的了解。

本系统采用现代化的前端技术栈构建，支持多种打卡频率设置、标签分类管理、数据导出备份等实用功能。无论是想要坚持每天早起、每日阅读、运动健身，还是完成特定周期的学习任务，都可以通过本系统进行有效的追踪和管理。

### 项目名称

个人打卡系统（Personal Check-in System）

### 核心功能

本系统提供了完整的打卡管理解决方案，核心功能包括以下几个方面：

**计划管理功能**支持用户创建多种类型的打卡计划，包括每日打卡、工作日打卡、周末打卡以及自定义间隔打卡等模式。用户可以为每个计划设置具体的执行日期范围、关联标签、提醒时间和个性化描述。系统还提供了计划暂停、恢复和归档功能，方便用户根据实际情况灵活调整计划执行状态。

**打卡记录功能**允许用户通过日历视图快速完成打卡操作，并支持最多7天内的补卡功能。每条打卡记录可以包含文字内容和多张图片，系统会自动记录打卡时间和是否迟到等状态信息。用户可以随时查看、编辑和删除自己的打卡记录。

**统计分析功能**提供了多维度的数据统计和分析能力，包括完成率统计、连续打卡天数、最长连续记录、周末与工作日对比、时段分布分析等。通过ECharts图表库，系统以直观的柱状图、折线图、饼图和热力图等形式展示数据，帮助用户了解自己的打卡习惯和坚持成果。

**数据管理功能**支持将打卡数据导出为JSON、CSV和Excel等多种格式，方便用户进行备份或进一步分析。同时系统也支持从备份文件中导入数据，实现数据的迁移和恢复。

**提醒通知功能**集成了浏览器通知API，用户可以为每个打卡计划设置提醒时间。系统支持提前提醒设置（5分钟、15分钟、30分钟），还提供了勿扰时段功能，避免在休息时间受到打扰。

### 目标用户

本系统适合以下类型的用户群体：想要养成早起、运动、阅读等日常习惯的个人用户；需要追踪周期性任务完成情况的学生和职场人士；希望记录和展示自己坚持成果的自律追求者；以及任何需要简单高效工具来管理日常打卡的人群。

## 技术栈

### 前端框架

本系统采用Vue 3作为前端核心框架，利用其强大的响应式数据绑定和组件化开发能力。Vue 3引入了Composition API，使得代码组织更加灵活，逻辑复用更加便捷。配合Vite作为构建工具，开发体验流畅，热更新速度快，生产构建效率高。

### UI组件库

Element Plus是Vue 3的官方推荐UI组件库，本系统使用它构建了完整的用户界面。Element Plus提供了丰富的组件，包括表单元素、对话框、数据表格、日期选择器等，大大加快了开发进度。其设计风格简洁现代，自带深色模式支持，能够满足大多数业务场景的需求。

### 图表可视化

ECharts是百度开源的可视化图表库，本系统使用它来实现各种统计图表的展示。通过Vue-ECharts封装，可以方便地在Vue组件中使用ECharts的所有功能。系统实现了柱状图展示各类统计数据、折线图展示趋势变化、饼图展示占比分布、热力图展示打卡频率日历等功能。

### 日历组件

FullCalendar是功能最全面的日历组件库之一，本系统使用@fullcalendar/vue3包来实现日历视图。系统支持月视图和周视图切换，可以显示每天的打卡任务和完成状态。FullCalendar提供了丰富的事件处理和交互功能，使得日历操作流畅自然。

### 数据存储

IndexedDB是浏览器内置的本地数据库，本系统通过Dexie.js库来操作IndexedDB。Dexie提供了一个简洁优雅的API，让数据库操作变得像使用普通JavaScript数组一样简单。相比LocalStorage，IndexedDB可以存储大量结构化数据，非常适合存储打卡记录等业务数据。

### 状态管理

Pinia是Vue官方推荐的新一代状态管理库，相比Vuex更加轻量和简洁。本系统使用Pinia管理用户认证状态、打卡计划列表、打卡记录、标签数据和系统设置等全局状态。每个功能模块都有独立的Store，便于维护和扩展。

### 其他依赖

本系统还使用了以下辅助库：Vue Router用于页面路由管理，支持导航守卫和路由参数传递；Day.js用于日期时间处理，这是一个轻量级的时间库，API设计与Moment.js兼容但体积小得多；VueUse是Vue组合式API的工具库，提供了大量实用的Composition函数；XLSX库用于生成Excel格式的导出文件。

## 功能特性

### 用户认证

系统提供了完整的用户认证功能，包括用户注册、登录、退出登录等基本操作。用户注册时需要设置用户名和密码，系统会对密码进行加密存储。登录成功后，系统会将用户信息存储在本地状态中，同时使用SessionStorage保存登录状态，确保页面刷新后登录状态不会丢失。

### 计划管理

**创建计划**：用户可以通过计划表单创建新的打卡计划，支持设置计划名称、描述、打卡频率、日期范围、标签关联和提醒设置等丰富选项。

**编辑计划**：已创建的计划可以随时修改各项设置，包括基本信息调整、频率规则变更、标签关联更新等。编辑操作不会影响已有的打卡记录。

**暂停与恢复**：当用户因出差、生病等原因无法继续打卡时，可以暂停计划执行。暂停后的计划不会生成新的打卡任务，但历史记录会保留。状态恢复后，计划将继续正常执行。

**归档功能**：对于已完成或不再需要的计划，用户可以选择归档处理。归档后的计划会从主列表中移除，但仍可通过筛选功能查看。

**删除计划**：计划可以被永久删除，删除时会同时删除该计划下的所有打卡记录。系统会要求用户输入计划名称进行二次确认，防止误操作。

### 日历视图

**月视图**：以月为单位展示日历，每天可以显示打卡任务的数量和完成状态。已完成的任务显示为绿色勾选标记，待完成任务显示为普通标记。

**周视图**：以周为单位展示详细的任务列表和时间安排，适合需要精确规划每天任务的用户。

**快速打卡**：点击日历上的任意日期即可打开打卡对话框，显示当日所有待打卡的计划，支持快速选择完成打卡。

**补卡功能**：系统支持补录最近7天内的打卡记录。超出7天范围的日期不可点击补卡，确保数据的时效性。补卡记录会被标记为迟到状态。

**视图切换**：用户可以通过按钮或键盘快捷键在月视图和周视图之间切换。按M键切换视图，按T键快速回到今天，按左右箭头键切换上下一周期。

### 统计分析

**基础统计**：显示总打卡次数、完成率、连续打卡天数、最长连续天数等核心指标。这些数据帮助用户快速了解自己的打卡成果。

**时间范围筛选**：支持按今日、本周、本月、本年等预设范围筛选统计数据，也可以自定义日期范围进行精确分析。

**计划与标签筛选**：可以按单个或多个计划、标签进行数据筛选，查看特定维度的打卡情况。

**周末与工作日对比**：分别统计周末和工作日的打卡数据，计算各自的完成率和日均打卡次数，展示差异对比。

**时段分析**：分析用户在各时段（凌晨、上午、下午、晚上）的打卡习惯，识别最佳打卡时段，并给出个性化建议。

**趋势图表**：通过折线图展示打卡次数的时间趋势，通过柱状图展示不同周期的对比数据，帮助用户发现规律和改进方向。

### 数据导出

**JSON导出**：将所有打卡数据导出为JSON格式，包含用户信息、标签、打卡计划和记录等完整数据结构。文件名格式为“打卡数据备份_YYYYMMDD_HHMMSS.json”。

**JSON导入**：支持从JSON备份文件导入数据，提供全量覆盖和部分导入两种模式。全量覆盖会清空现有数据后导入，部分导入会基于ID去重只导入新数据。

**CSV导出**：将打卡记录导出为CSV格式，UTF-8编码确保中文显示正常。支持选择导出字段，支持按日期、计划和标签筛选。

**Excel导出**：导出包含多个工作表的Excel文件，包括汇总统计、打卡记录明细和计划列表三个工作表。支持自动列宽和样式美化。

### 提醒功能

**浏览器通知**：使用浏览器原生通知API发送打卡提醒，需要用户授权通知权限。系统会检测浏览器类型并提供详细的开启指引。

**提醒时间设置**：每个计划可以设置独立的提醒时间，支持设置是否提前提醒（5分钟、15分钟、30分钟）。

**勿扰时段**：支持设置全局或单个计划的勿扰时段，在指定时间范围内不会发送通知。例如设置晚上10点到早上8点为勿扰时段。

**提醒历史**：记录每次提醒的发送时间和用户点击情况，统计总提醒数、已发送数、已点击数和点击率。

## 快速开始

### 环境要求

在开始安装和运行项目之前，请确保您的开发环境满足以下要求：

**Node.js版本**：建议使用Node.js 18.0.0或更高版本。您可以通过在终端执行node -v命令来检查当前安装的Node.js版本。如果版本过低，请前往Node.js官网下载安装最新版本。

**包管理器**：本项目支持多种包管理器，包括npm（Node.js自带）、yarn和pnpm。建议使用npm或pnpm以获得更好的依赖管理体验。

**浏览器要求**：为了获得最佳的使用体验，建议使用以下浏览器之一：Google Chrome 80或更高版本、Mozilla Firefox 75或更高版本、Microsoft Edge 80或更高版本、Apple Safari 14或更高版本。浏览器需要支持IndexedDB和Notification API。

### 安装步骤

克隆项目仓库后，进入项目根目录并执行依赖安装命令。首先确保已安装项目所需的所有依赖包，这些依赖定义在package.json文件中。

使用npm安装依赖的完整命令如下：

```bash
npm install
```

这个命令会根据package.json中定义的所有依赖项，包括Vue 3、Vite、Element Plus、ECharts、FullCalendar、Dexie等库，自动下载并安装到项目的node_modules目录中。安装过程可能需要几分钟时间，请耐心等待。

如果您使用的是pnpm包管理器，可以使用以下命令：

```bash
pnpm install
```

如果您使用的是yarn包管理器，可以使用以下命令：

```bash
yarn install
```

### 运行项目

依赖安装完成后，可以使用开发服务器启动项目。在项目根目录下执行以下命令：

```bash
npm run dev
```

Vite开发服务器会启动，通常默认运行在http://localhost:5173地址。您可以在浏览器中打开这个地址来访问应用。开发服务器支持热模块替换（HMR），修改代码后浏览器会自动刷新以显示最新更改，无需手动刷新页面。

首次启动时，如果端口5173已被占用，Vite会自动尝试使用下一个可用端口，如5174或5175。请留意终端输出的实际访问地址。

### 构建部署

当项目开发完成需要部署到生产环境时，需要执行构建命令生成优化后的静态文件。在项目根目录下执行以下命令：

```bash
npm run build
```

构建完成后，会在项目根目录生成dist文件夹，里面包含所有优化压缩后的静态文件。这些文件可以直接部署到任何静态文件服务器上。

部署到服务器时，需要注意以下几点：由于系统使用HTML5 History模式进行路由管理，服务器需要配置将所有请求重定向到index.html。常用的部署方案包括Nginx配置try_files规则、Netlify或Vercel等静态托管平台。

如果您想要在本地预览构建后的效果，可以执行以下命令：

```bash
npm run preview
```

这会启动一个本地静态文件服务器，预览实际的生产环境效果。

### 目录职责说明

**src/components/**目录存放所有可复用的Vue组件，按功能模块进行分组。charts子目录包含各类图表组件，采用ECharts封装，便于在多个页面中复用。checkin子目录包含打卡相关的交互组件，包括打卡对话框、快速打卡按钮和补卡对话框等。

**src/views/**目录包含所有页面级组件，每个功能模块有独立的子目录。页面组件负责组合使用各种基础组件，完成特定业务场景的界面展示和交互处理。

**src/stores/**目录使用Pinia管理应用的全局状态。每个Store对应一个业务领域，包括用户认证、打卡计划、打卡记录、标签和系统设置。这种按领域划分的方式使得状态管理清晰有序。

**src/database/**目录封装了所有与IndexedDB数据库交互的代码。db.ts定义数据库的表结构和版本管理，dal.ts提供数据访问方法供Store调用。这种分层设计将数据持久化逻辑与业务逻辑分离。

**src/utils/**目录包含各类工具函数，如浏览器通知的封装、提醒引擎的实现、日期时间的格式化等。这些工具函数可以在多个组件中复用，提高代码复用性。

## 数据模型

### 用户模型

用户数据存储在IndexedDB的users表中，主要字段包括用户ID、用户名（唯一）、密码哈希值、创建时间和最后登录时间。密码使用单向哈希算法加密存储，系统中不会明文保存任何用户密码。

```typescript
interface User {
  id: string;          // 用户唯一标识符
  username: string;   // 用户名（登录凭证）
  password: string;   // 密码哈希值
  createdAt: Date;     // 账户创建时间
  lastLoginAt: Date;   // 最后登录时间
}
```

### 标签模型

标签用于对打卡计划进行分类管理，存储在IndexedDB的tags表中。每个用户可以创建多个标签，标签之间相互独立。

```typescript
interface Tag {
  id: string;          // 标签唯一标识符
  userId: string;      // 所属用户ID
  name: string;        // 标签名称
  icon: string;        // 标签图标名称
  color: string;       // 标签颜色（十六进制格式）
  isDefault: boolean;  // 是否为系统默认标签
  createdAt: Date;     // 创建时间
}
```

### 打卡计划模型

打卡计划是用户创建的核心业务实体，定义了需要坚持完成的任务。计划数据存储在IndexedDB的plans表中。

```typescript
interface Plan {
  id: string;                    // 计划唯一标识符
  userId: string;                // 所属用户ID
  name: string;                  // 计划名称
  description: string;          // 计划描述
  tagIds: string[];              // 关联的标签ID列表
  frequency: FrequencyType;      // 打卡频率类型
  customRules: CustomRule[];     // 自定义规则
  startDate: Date;               // 计划开始日期
  endDate: Date | null;          // 计划结束日期（null表示无期限）
  targetCount: number;           // 目标打卡次数
  reminderTime: string;          // 提醒时间（HH:mm格式）
  reminderEnabled: boolean;      // 是否启用提醒
  status: PlanStatus;            // 计划状态
  createdAt: Date;               // 创建时间
  updatedAt: Date;               // 更新时间
}

type FrequencyType = 'daily' | 'workdays' | 'weekends' | 'weekly' | 'custom';

interface CustomRule {
  type: 'week' | 'interval';
  days?: number[];      // 星期几（0-6）
  interval?: number;    // 间隔天数
}

type PlanStatus = 'active' | 'paused' | 'archived';
```

## API文档

### 认证相关

**用户注册**：在注册页面填写用户名和密码后提交，系统会验证用户名是否已存在，如果不存在则创建新用户。注册成功后自动登录并跳转到首页。

**用户登录**：在登录页面填写用户名和密码后提交，系统验证凭证是否正确。登录成功后保存会话信息，跳转到首页。

**用户退出**：清除本地会话信息，返回登录页面。

### 计划相关

**创建计划**：通过POST请求创建新的打卡计划，需要提供计划的完整信息。创建成功后返回计划ID。

**查询计划列表**：获取当前用户的所有打卡计划列表，支持按状态筛选（进行中、已暂停、已归档）。

**查询计划详情**：根据计划ID获取单个计划的详细信息，包括统计数据和打卡记录列表。

**更新计划**：根据计划ID更新计划信息，支持更新所有可编辑字段。

**删除计划**：根据计划ID删除计划，同时删除该计划下的所有打卡记录。

**暂停/恢复计划**：修改计划的状态字段，实现暂停和恢复功能。

### 记录相关

**创建打卡记录**：在打卡对话框中填写内容并提交，创建新的打卡记录。系统会自动记录打卡时间和用户信息。

**查询记录列表**：获取打卡记录列表，支持按计划、日期范围、标签等条件筛选，支持分页查询。

**更新记录**：修改打卡记录的内容和图片。

**删除记录**：删除指定的打卡记录。

### 统计相关

**基础统计**：计算并返回总打卡次数、完成率、连续天数、最长连续天数等基础指标。

**时间范围统计**：根据指定的时间范围筛选数据，计算该范围内的统计指标。

**对比分析**：计算工作日与周末的对比数据、时段分布数据等。

**趋势数据**：获取指定时间段内的打卡趋势数据，用于绘制趋势图表。

### 数据导出相关

**导出JSON**：生成包含所有数据的JSON文件并触发下载。

**导出CSV**：根据筛选条件生成CSV文件并触发下载。

**导出Excel**：生成包含多个工作表的Excel文件并触发下载。

**导入JSON**：读取用户选择的JSON文件，校验数据格式，执行导入操作。

## 常见问题

### 如何重置密码？

由于本系统将用户数据存储在浏览器的本地数据库中，不存在服务端密码找回机制。如果您忘记了密码且无法登录，可以尝试以下方法：

**清除数据重新注册**：在浏览器设置中清除本站点的所有数据（IndexedDB和LocalStorage），然后重新注册账号。需要注意的是，此方法会清除所有打卡数据，请提前做好数据备份。

**从备份恢复**：如果您之前有导出过JSON格式的数据备份，可以在清除数据后重新注册账号，然后导入备份文件恢复大部分数据。

建议用户养成定期导出数据备份的习惯，以防止意外情况导致数据丢失。

### 数据如何备份？

系统提供了多种数据备份方式，确保您的打卡数据安全：

**JSON格式备份**：最完整的备份方式，可以导出所有数据（用户信息、标签、计划、记录）。在数据导出页面点击“导出JSON”按钮即可生成备份文件。备份文件名格式为“打卡数据备份_日期时间.json”。

**Excel格式备份**：适合需要进一步分析或制作报表的场景。可以导出包含汇总统计、打卡明细和计划列表的Excel文件。

**CSV格式备份**：适合导入到其他数据分析工具中使用，支持自定义导出字段。

建议用户至少每月进行一次完整备份，在重要节点（如完成一个大周期目标）时也进行一次备份。备份文件应妥善保存在可靠的位置。

### 为什么通知不工作？

浏览器通知功能需要满足以下条件才能正常工作：

**浏览器权限**：首次使用时，浏览器会询问是否允许发送通知，您需要点击允许。如果之前拒绝了权限，需要在浏览器设置中手动开启。请参考系统设置页面的通知权限引导。

**浏览器支持**：部分浏览器或浏览器版本可能不支持通知功能。系统会自动检测并在不支持时给出提示。

**页面后台运行**：通知功能需要页面处于打开状态才能触发。如果您关闭了浏览器或切换到其他标签页，通知可能无法及时发送。

**系统通知设置**：除了浏览器权限，您的操作系统也可能设置了通知拦截。请检查操作系统的通知设置，确保允许浏览器发送通知。

### 如何导出数据？

在系统的数据导出页面可以找到各种导出功能：

**完整导出**：点击“导出JSON”按钮，系统会生成包含所有数据的备份文件并自动下载。这是最完整的备份方式。

**筛选导出**：在使用CSV或Excel导出时，可以先设置日期范围、选择要导出的计划和标签，然后预览导出的数据，确认无误后再点击导出按钮。

**字段选择**：在导出CSV或Excel时，可以勾选需要导出的字段，不需要的字段可以不选。必填字段无法取消选择。

### 如何设置合理的打卡计划？

创建有效的打卡计划需要注意以下几点：

**目标明确**：计划名称要具体清晰，如“每天早起”比“养成好习惯”更具体，也更容易执行和追踪。

**频率适中**：如果是刚开始培养习惯，建议从较低的频率开始，如每周3次，等习惯形成后再增加频率。过于激进的计划容易导致放弃。

**时间固定**：为计划设置固定的提醒时间，将其融入日常作息中。固定的时间点更容易形成记忆。

**关联已有习惯**：将新计划与已有的习惯关联，如“早餐后阅读30分钟”，可以利用已有习惯带动新习惯的养成。

### 打卡记录可以修改吗？

是的，可以修改。您可以随时编辑之前的打卡记录，包括修改打卡内容、添加或删除图片等。编辑操作不会影响与该记录关联的计划统计数据。

补卡记录（超过当天但7天内的打卡）会被标记为迟到状态，但这些标记是为了帮助您了解自己的打卡习惯，不会对您的坚持成果产生负面影响。

### 如何删除我的账户？

系统目前不提供自助注销账户的功能。如果您需要清除所有数据，可以在浏览器设置中清除本站点的所有数据，包括IndexedDB和LocalStorage。

清除数据后，您注册的账户信息、所有的打卡计划和记录都会被永久删除，此操作不可恢复。在执行此操作前，请务必确保已经完成了数据备份。

### 数据存储在哪里？

您的所有数据都存储在浏览器的本地IndexedDB数据库中。这意味着数据仅存在于您当前使用的浏览器和设备上，不会同步到其他设备或浏览器。

如果您更换浏览器或设备，除非使用导入功能从备份文件中恢复，否则之前的数据不会自动迁移过来。建议在更换设备前导出完整的数据备份。
